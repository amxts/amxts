A plugin keeps its data in MySQL or MariaDB with `Database` :since{v="0.3.1"}, a global - no
import line:

```ts
interface Record {
	name: string;
	time: number;
}

const db = new Database(env("MYPLUGIN_DB", ""));

server.addCommand("/top", async ({ player }) => {
	const top = await db.query<Record>("SELECT name, time FROM records WHERE map = ? ORDER BY time LIMIT 10", [server.map]);
	top.forEach((record, i) => player.print(`${i + 1}. ${record.name} ${record.time.toFixed(2)}`));
});
```

A query runs in the background. The game does not wait for it: its result
arrives on a later server frame, never inside the call that sent it.

## The address

`new Database(url)` takes the database's address:

```
mysql://user:password@host:3306/database?ssl-mode=preferred
```

The port is `3306` when left out. A user or password with `@`, `:` or `/` in
it is written with `%40`, `%3A`, `%2F`.

Keep the address out of the code: read it with
[`env`](../3.game/05.cvars.md#secrets-and-server-settings-env) from the server's `addons/amxts/.env`,
so the password stays on the server:

```ini
MYPLUGIN_DB=mysql://kz:s3cret@127.0.0.1:3306/kz
```

`ssl-mode` says whether the connection is encrypted, with the names MySQL's
own clients use:

| `ssl-mode` | Meaning |
| --- | --- |
| `preferred` | TLS when the server offers it; the default |
| `disabled` | never TLS |
| `required` | TLS, or no connection; the server's certificate is not checked |
| `verify-ca` | TLS with a certificate a trusted authority vouches for |
| `verify-identity` | as `verify-ca`, and the certificate names the address's host |

MySQL 8 users (`caching_sha2_password`) and older ones
(`mysql_native_password`) both sign in, with or without TLS.

## Reading rows

`db.query<T>(sql, params)` runs a statement that reads rows and gives them
as `T[]` - `T` an interface of the columns, declared beside your code. Each
`?` in the statement takes the next value of `params`:

```ts
interface Player {
	steamId: string;
	points: number;
	title?: string;
}

const found = await db.query<Player>("SELECT steamId, points, title FROM players WHERE steamId = ?", [player.steamId]);
const me = found[0];   // undefined when there is no such row
```

A column the interface does not name is skipped. A field a row lacks keeps
the default the interface gives it, stays `undefined` when it is optional,
and is a `TypeError` naming it otherwise; a column that is `NULL` is `null`.

Values go through `?`, never into the SQL text: the database receives them
apart from the statement, so a name with a quote in it is just a name. A
value is text, a number, a boolean or `null`, and one list may hold all of
them: `[player.name, time, true, null]`.

What a column becomes:

| Column | Value |
| --- | --- |
| `INT`, `BIGINT`, `TINYINT`, `FLOAT`, `DOUBLE`, `DECIMAL`, `YEAR`, `BIT` | a number |
| `CHAR`, `VARCHAR`, `TEXT`, `ENUM`, `SET`, `JSON` | text |
| `DATE`, `DATETIME`, `TIMESTAMP`, `TIME` | text as MySQL writes it: `"2026-10-12 18:30:00"` |
| `NULL` | `null` |

## Changing rows

`db.execute(sql, params)` runs a statement that changes rows - `INSERT`,
`UPDATE`, `DELETE`, `CREATE TABLE` - and gives `{ insertId, affectedRows }`:

```ts
const { insertId } = await db.execute("INSERT INTO records (steamId, map, time) VALUES (?, ?, ?)", [player.steamId, server.map, time]);
```

`insertId` is the `AUTO_INCREMENT` id of the row inserted, `0` when there was
none; `affectedRows` is how many rows the statement inserted, changed or
deleted - for an `UPDATE`, the rows it matched.

## Errors

A query that fails rejects its promise with a `DatabaseError`: `message` is
the server's, `code` its error number (`1062` for a duplicate key) and
`sqlState` its SQLSTATE (`"23000"`). When the query did not reach the
server - no connection, a wrong address - `code` is `0` and `message` says
why.

```ts
try {
	await db.execute("INSERT INTO players (steamId) VALUES (?)", [player.steamId]);
} catch (error) {
	if ((error as DatabaseError).code == 1062) return;   // already there
	console.error(`could not save ${player.name}: ${error.message}`);
}
```

## Transactions

`db.transaction(fn)` runs `fn` with a transaction `tx`: what `fn` sends
through `tx.query` and `tx.execute` is committed when `fn` returns, and
rolled back when it throws - the error goes on to the caller. The promise
gives what `fn` returned:

```ts
const runId = await db.transaction(async (tx) => {
	const { insertId } = await tx.execute("INSERT INTO runs (steamId, time) VALUES (?, ?)", [player.steamId, time]);
	await tx.execute("UPDATE players SET runs = runs + 1 WHERE steamId = ?", [player.steamId]);
	return insertId;
});
```

A transaction has a connection of its own while it runs; up to four run at
once for one address, and a fifth waits for one of them to end.

::: warning
- **One connection an address.** Every plugin that opens the same address
  shares one connection, and its queries run one after another in the order
  sent; the connection stays open from map to map. A connection the server
  closed is opened again for the next query. A query under way when the
  connection is lost fails and is not sent again: an `INSERT` the server
  may have run is not run twice.
- **A query may take a minute.** When the server says nothing for 60
  seconds in the middle of a query, the query fails.
- **A result is read whole,** at most 64 MB: ask for the rows you need.
- **`TINYINT(1)` is a number,** `0` or `1`, as MySQL keeps a `BOOLEAN`:
  read it into a `number` field.
- **A whole number past 2^53** (`9007199254740993`, a 64-bit id) loses its
  last digits in a `number`: select it as text, `CAST(id AS CHAR)`, into a
  `string` field.
:::

## Other databases

The scheme of the address picks who answers it. `mysql://` is built in;
another database - a file, a web service, a Pawn module's natives - is a
provider a library or the plugin registers with `Database.register`, and a
plugin then opens its addresses as it opens MySQL's.

A provider is a function that gives a connection for an address:

```ts
class LogConnection implements DatabaseConnection {
	constructor(public url: string) {}

	query(sql: string, params: DatabaseValue[]): Promise<string> {
		return Promise.resolve<string>("[]");   // rows as JSON text: [{"name":"a","time":1.5}]
	}

	execute(sql: string, params: DatabaseValue[]): Promise<ExecuteResult> {
		console.log(`${sql} ${JSON.stringify(params)}`);
		return Promise.resolve<ExecuteResult>({ insertId: 0, affectedRows: 0 });
	}

	begin(): Promise<DatabaseTransaction> {
		return Promise.reject<DatabaseTransaction>(new DatabaseError("the log has no transactions"));
	}

	close(): void {}
}

Database.register("log", (url: string): DatabaseConnection => new LogConnection(url));

const log = new Database("log://anything");
```

- `query` gives the rows as JSON text, an array of objects; `Database`
  reads it into the caller's `T`.
- `execute` gives `{ insertId, affectedRows }`.
- `begin` gives a `DatabaseTransaction` - `query`, `execute`, `commit()`
  and `rollback()` - or rejects when the database has none.
- A connection runs its queries in the order it is given them.

`JSON.stringify(params)` writes the values as a JSON array, ready to send to
a web service.

A provider in a library registers itself when the library is imported, so
a plugin that uses it writes one line:

```ts
import "@myorg/sqlite";

const db = new Database("sqlite://data/myplugin.db");
```

An address whose scheme has no provider rejects every query with a
`DatabaseError` that names the schemes there are.
