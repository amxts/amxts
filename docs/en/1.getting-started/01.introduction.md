amxts lets you write AMX Mod X plugins for Counter-Strike 1.6 in TypeScript.
A plugin is an ordinary `.ts` file: familiar types, classes, closures,
`async`/`await`, events you listen to. It runs on the server next to your
Pawn plugins, and the two call each other.

```ts
plugin({ name: "Welcome", version: "1.0.0", author: "you" });

server.addEventListener("putInServer", (event) => {
	event.player.print(`Welcome, ${event.player.name}!`);
});

game.addEventListener("takeDamage", (event) => {
	if (event.attacker.team == event.player.team) event.preventDefault();   // no team damage
});

server.addCommand("/heal", ({ player }) => {
	if (player.health < 100) player.health = 100;
});
```

## What you get

- **TypeScript as you know it:** `number`, `string`, `boolean`, arrays, `Map`,
  classes and interfaces, optional fields, closures, template strings.
- **Players and entities as objects:** `player.health = 100`, `player.team`,
  `player.hideHud.push("money")`, `Entity.findAll({ classname: "grenade" })`
  ([Players and entities](../3.game/01.entities.md)).
- **Events as in the browser:** `server.addEventListener("putInServer", ...)`
  for the server, `game.addEventListener("takeDamage", ...)` for the game,
  with `event.preventDefault()` ([Game events](../2.core/02.hooks.md)).
- **An editor that knows the game:** every native, every game event and every
  entity field comes with its type and a description; a typo is a red line,
  not an error on the server.
- **Waiting without blocking:** `await sleep(1000)`, `await useFetch<Stats>(url)`,
  cancelled on its own when the player leaves ([Async](../2.core/04.async.md)).
- **Save and play:** `amxts dev` rebuilds a plugin on save and reloads it on
  the running server, without a map change ([Getting started](02.quick-start.md)).
- **Tests without a game server:** your plugin runs against a fake server with
  `npx amxts test` ([Testing](../7.testing/01.index.md)).
- **Pawn plugins keep working:** a TypeScript plugin exports natives and
  forwards for them and calls theirs ([Natives](../6.pawn/01.natives.md),
  [Forwards](../2.core/03.forwards.md)).

## How it runs

The build compiles each plugin ahead of time to machine code, a `.aot` file.
The `amxts_amxx` module, an AMX Mod X module you install on the server, loads
these files and runs them inside AMX Mod X. Every native the server has - of
AMX Mod X, ReAPI, the other modules and other plugins - is a typed function a
plugin can call.

## What the server needs

- AMX Mod X 1.9 or later.
- The `amxts_amxx` module, on a Windows or a Linux server: `amxts_amxx.dll`
  or `amxts_amxx_i386.so`, which the line `amxts_amxx` in `modules.ini` finds
  on either.
- For every game event of ReGameDLL's own as the game raises it
  (`playerSpawn`, `roundEnd`, …): ReGameDLL, and ReHLDS for the engine's;
  ReAPI is not needed. The entity properties and the player actions (`give`,
  `respawn`, …) work without them too - amxts does them with the game's own
  functions - and most game events through the game's other hooks, some
  with less ([installing](04.install.md#what-the-server-needs)).

::: warning ReHLDS is recommended
amxts is built and tested on ReHLDS with ReGameDLL, with ReAPI and without
it, and on Valve's own HLDS. On plain HLDS a plugin is written the same, and
the game events come through the entities' functions, the game's log and its
messages: most are heard only after the game has acted, so they cannot be
stopped or changed, and a few - `fallDamage`, `giveDefaultItems`, the
player's movement - are not heard at all
([a server without ReGameDLL](../2.core/02.hooks.md#a-server-without-regamedll)).
:::

How to put amxts on a server, and where each file goes:
[Installing on a server](04.install.md).

What amxts cannot do yet, and what to write instead, is on

## Modules

A module is a package of TypeScript that plugins share
([Shared modules](../5.modules/01.shared-modules.md)). A project lists the modules it uses
in `amxts.config.ts`: a module one of them requires comes along, and a module
no plugin uses is not built. The official ones:

- **menu-core** — menus from INI, YAML or JSON files or from code
  ([Menus](../../modules/en/menu-core.md)): the module to add for a server's
  menus. A quick menu built in code alone is the core's `Menu`
  ([menus](../2.core/01.plugin.md#menus));
- **config-core** — configs in INI, YAML or JSON, read into typed objects
  ([Configs](../../modules/en/config-core.md));
- **resemiclip** — who walks through whom, as a rule over two players, over
  the ReSemiclip module ([resemiclip](https://github.com/amxts/resemiclip));
- **ftp** :since{v="0.2"} — FTP, FTPS and SFTP: upload, download and list files on another
  server, every call a promise ([ftp](https://github.com/amxts/ftp)).

`useFetch` and `fetch` for web requests come with amxts ([HTTP](../4.data/03.http.md)). More modules
are in the [modules catalog](/modules), and you can
[write your own](../5.modules/02.creating-a-module.md).
