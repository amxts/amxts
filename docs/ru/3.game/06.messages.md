---
title: Сообщения
---

Сервер говорит каждому клиенту, что рисовать и играть, сообщениями: строка
чата, значок HUD, часы раунда, сообщение об убийстве. Плагин слышит сообщение
до того, как оно ушло, читает его, меняет или останавливает:

```ts
server.addMessageListener("death", (event) => {
	if (event.headshot) server.print(`${event.killer?.name} - headshot - ${event.victim?.name}`);
});

server.addMessageListener("text", (event) => {
	if (event.text == "#Round_Draw") event.preventDefault();   // клиент его не получит
});

server.addMessageListener("team", (event) => {
	if (event.team == "SPECTATOR") console.log(`${event.target?.name} наблюдает`);
});

server.addMessageListener("roundTime", (event) => {
	event.seconds = 90;                                         // часы показывают 90
});
```

`server.removeMessageListener("death", listener)` снимает обработчик: передайте
то же имя и ту же функцию, что добавляли. До плагина доходят только те
сообщения, которые он слушает.

Имя сообщения пишется строкой, и редактор подсказывает имена, у каждого —
для чего игра шлёт это сообщение и как его называет сама игра: `death` — это
`DeathMsg` игры, `chat` — её `SayText`. Все они — в таблице в конце страницы.

Несколько сообщений игры для плагина — одно и то же, и одно имя слышит их
все: `progressBar` — это `BarTime` и `BarTime2`, которое только добавляет, с
какого места полоса начинается. У события есть поля их всех, а `event.name`
говорит, какое пришло; поле, которого в пришедшем сообщении нет, читается как
`0`, `null` или пусто, а присваивание ему ничего не меняет — `startPercent` у
`BarTime` равен `0`.

```ts
server.addMessageListener("progressBar", (event) => {
	console.log(`${event.name}: ${event.seconds} с от ${event.startPercent}%`);
});
```

## Событие

`event.player` — игрок, которому идёт сообщение, `null` — если всем, поэтому
игрок, о котором сообщение, — отдельное поле: `target` или его роль —
`killer`, `victim`, `sender`. `preventDefault()` останавливает сообщение.
`event.name` — имя сообщения у игры, `"DeathMsg"` у `death`.

Каждое сообщение игра пишет по своей раскладке, и у сообщения с известной
раскладкой — а это почти все, что шлёт Counter-Strike, — на каждый аргумент
есть поле с именем и типом: игрок — `Player` (`null` — никто), признак —
`boolean`, команда — `Team`, оружие — `WeaponKind`, маска — массив имён, время
— в секундах. Редактор их подсказывает. Присвоить полю — изменить то, что
получит клиент: `event.team = "CT"`.

```ts
server.addMessageListener("hideWeapon", (event) => {
	event.flags = event.flags.concat(["money"]);               // деньги тоже скрыты
});
```

Сообщение без известной раскладки — прогресс ботов, тексты подсказчика —
читается по месту аргументов, через `event.args`, которые есть у любого
сообщения для того, чего не покрывают его поля:

```ts
server.addMessageListener("botProgress", (event) => {
	console.log(`${event.args.length} ${event.args.number(0)}`);
});
```

`event.args.number(i)` и `event.args.text(i)` читают аргумент на месте `i`,
`0` — первый; `isText(i)` говорит, какой он; `setNumber(i, value)` и
`setText(i, value)` его меняют.

Аргумент, который сообщение не записало, — цвет `statusIcon`, когда значок
прячут, `params` текста без подстановок, — читается как `0` или пусто, а
присваивание ему ничего не меняет. Имя, для которого у игры нет сообщения, —
ошибка сборки.

::: warning
Сообщение, которое плагин шлёт через `message_begin`, до обработчиков не
доходит: они слышат то, что идёт через функции движка, как и
`register_message` AMX Mod X. Посланное через `emessage_begin` доходит, как и
то, что шлёт `player.screen`, и то, что шлёт `player.money`, когда ему
присваивают.
:::

::: warning Плагины на Pawn на том же сообщении
`register_message` или `set_msg_block` плагина на Pawn слышит сообщение
первым, и AMX Mod X отправляет его таким, каким его оставил этот плагин.
Обработчики тогда слышат его таким, каким его написала игра, и что они в нём
меняют или блокируют, не отправляется; консоль сервера говорит об этом один
раз для сообщения.
:::

::: warning Меню — тоже сообщения
`menu` — любое текстовое меню, которое видит игрок: игры и плагина тоже —
`Menu`, меню menu-core, `show_menu` плагина на Pawn. Если блокировать меню
по слову из текста, скроется и меню плагина с этим словом. Меню самой игры
приходят её ключами — `#Team_Select`, `#CT_Select`, `#Terrorist_Select`,
`#RadioA`, — поэтому сравнивайте `event.text` с ними. Заблокированное
`menu` или `vguiMenu` до игрока не доходит, и меню, которое уже у него на
экране, сохраняет свои клавиши.
:::

## Отправка сообщения :since{v="0.3"}

То, что плагин отправляет часто, имеет свой метод — `player.screen.fade()`,
`player.money`, `player.showMotd()`. Любое другое сообщение из таблицы ниже,
у которого есть поля, отправляется по имени, с теми же полями, что читают
его слушатели:

```ts
player.send("team", { target: other, team: "CT" });          // одному игроку
server.send("score", { target: player, frags: 10, deaths: 2, team: "CT" });
server.send("bombDrop", { origin: [0, 0, 64] }, { near: player.origin });   // тем, кто видит точку
```

Редактор показывает имена, которые принимает `send`, и поля каждого.
Пропущенное поле уходит как `0` или пустой текст, так что сообщение
отправляется целиком; слушатели слышат его по пути, как сообщение самой игры.
`player.send` доходит до игрока гарантированно; `server.send` — до всех, а с
`near` — только до игроков, которые видят эту точку, без гарантии, как
эффекты. Имя нескольких сообщений отправляет то, в котором есть все их поля:
`progressBar` отправляет `BarTime2`.

::: warning Сообщение — это то, что увидит клиент
Клиент рисует то, что говорит сообщение: сообщение `team` красит имя игрока в
другой цвет, не переводя его в другую команду, сообщение `money` показывает
сумму, которой у него нет. Чтобы изменить игру, меняйте игрока
(`player.team`, `player.money`); сообщение отправляют, чтобы показать то,
чего игра не показывает.
:::
