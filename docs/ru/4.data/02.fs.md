title: Файлы
---

`~/fs` читает и пишет файлы так же, как `fs` в Node:

```ts
import * as fs from "~/fs";

const rulesFile = `${server.configsDir}/myplugin/rules.txt`;

server.addCommand("/rules", showRules);

function showRules(player: Player) {
	const text = fs.readFileSync(rulesFile);
	if (text == null) return;                  // файла нет

	for (const line of text.split("\n")) console.log(line);
	fs.appendFileSync(`${server.dataDir}/myplugin-rules.log`, `${player.name} прочитал правила\n`);
}
```

У каждой функции есть синхронная форма и форма с промисом, для `await`:

| Синхронная | С промисом | Что делает |
| --- | --- | --- |
| `readFileSync(path)` → `string \| null` | `readFile(path)` → `Promise<string>` | читает весь файл как текст |
| `writeFileSync(path, text)` → `boolean` | `writeFile(path, text)` → `Promise<void>` | записывает файл, заменяя то, что там было |
| `appendFileSync(path, text)` → `boolean` | `appendFile(path, text)` → `Promise<void>` | дописывает в конец, при необходимости создаёт файл |
| `existsSync(path)` → `boolean` | `exists(path)` → `Promise<boolean>` | есть ли такой файл или папка |
| `readdirSync(path)` → `string[] \| null` | `readdir(path)` → `Promise<string[]>` | имена в папке, без `.` и `..` |
| `mkdirSync(path, options?)` → `boolean` | `mkdir(path, options?)` → `Promise<void>` | создаёт папку; `{ recursive: true }` создаёт и недостающие папки выше |

```ts
import * as fs from "~/fs";

async function saveMap() {
	await fs.mkdir(`${server.dataDir}/myplugin`, { recursive: true });
	await fs.writeFile(`${server.dataDir}/myplugin/last-map.txt`, server.map);
}

fs.readFile("missing.txt").catch((error) => console.log(error.message));
// ENOENT: no such file or directory, open 'missing.txt'
```

## Пути

Путь задаётся относительно папки игры, `cstrike/`, как у любого плагина
AMX Mod X. `server.configsDir` — папка конфигов (`addons/amxmodx/configs`),
`server.dataDir` — папка данных (`addons/amxmodx/data`), где бы сервер их ни
держал. Храните файлы плагина в своей папке или под своим именем:
`configs/myplugin/`, `data/myplugin-stats.txt`.

## Текст

Файлы читаются и пишутся как текст в UTF-8. Файл читается целиком, какого бы
размера он ни был. Метка порядка байтов (BOM) в начале файла сохраняется, как
в Node.

## Когда не получилось

Синхронная функция сообщает об ошибке результатом: `null` у `readFileSync` и
`readdirSync`, `false` у `writeFileSync`, `appendFileSync` и `mkdirSync` —
например, если нет папки. Функция с промисом отклоняется с `Error`, чьё
сообщение начинается с `ENOENT`, как в Node (у `mkdir` — с `EEXIST or ENOENT`).

В обоих случаях работа делается сразу: к моменту, когда функция с промисом
вернулась, промис уже завершён.

## Операционная система

```ts
import { EOL, platform } from "~/os";

if (platform() == "linux") console.log("сервер на Linux");
const lines = ["first", "second"].join(EOL);   // "\r\n" в Windows, "\n" в Linux
```

`platform()` — это `"win32"` или `"linux"`, а `EOL` — перевод строки этой
системы.

В тесте фейковый сервер держит папку игры в памяти: `server.writeFile(path,
text)` — до того, как плагин читает, `server.file(path)` — после того, как
он записал ([Тесты](../7.testing/01.index.md)).
