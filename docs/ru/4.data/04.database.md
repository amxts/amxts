title: База данных
---

Плагин хранит данные в MySQL или MariaDB через `Database` :since{v="0.3.1"} —
глобальный класс, без строки импорта:

```ts
interface Record {
	name: string;
	time: number;
}

const db = new Database(env("MYPLUGIN_DB", ""));

server.addCommand("/top", async ({ player }) => {
	const top = await db.query<Record>("SELECT name, time FROM records WHERE map = ? ORDER BY time LIMIT 10", [server.map]);
	top.forEach((record, i) => player.print(`${i + 1}. ${record.name} ${record.time.toFixed(2)}`));
});
```

Запрос идёт в фоне. Игра его не ждёт: результат приходит на одном из
следующих кадров сервера, никогда — внутри вызова, который отправил запрос.

## Адрес

`new Database(url)` принимает адрес базы:

```
mysql://user:password@host:3306/database?ssl-mode=preferred
```

Без порта берётся `3306`. Пользователь или пароль с `@`, `:` или `/` пишется
через `%40`, `%3A`, `%2F`.

Держите адрес вне кода: читайте его через
[`env`](../3.game/05.cvars.md#секреты-и-настройки-сервера-env) из
`addons/amxts/.env` сервера, чтобы пароль оставался на сервере:

```ini
MYPLUGIN_DB=mysql://kz:s3cret@127.0.0.1:3306/kz
```

`ssl-mode` говорит, шифруется ли соединение, — названия те же, что у
клиентов самого MySQL:

| `ssl-mode` | Что значит |
| --- | --- |
| `preferred` | TLS, если сервер его предлагает; по умолчанию |
| `disabled` | никогда не TLS |
| `required` | TLS или никакого соединения; сертификат сервера не проверяется |
| `verify-ca` | TLS с сертификатом, за который ручается доверенный центр |
| `verify-identity` | как `verify-ca`, и сертификат выдан на хост из адреса |

Входят и пользователи MySQL 8 (`caching_sha2_password`), и старые
(`mysql_native_password`), с TLS и без.

## Чтение строк

`db.query<T>(sql, params)` выполняет запрос, который читает строки, и отдаёт
их как `T[]`: `T` — интерфейс колонок, объявленный рядом с вашим кодом.
Каждый `?` в запросе берёт следующее значение из `params`:

```ts
interface Player {
	steamId: string;
	points: number;
	title?: string;
}

const found = await db.query<Player>("SELECT steamId, points, title FROM players WHERE steamId = ?", [player.steamId]);
const me = found[0];   // undefined, если такой строки нет
```

Колонка, которой нет в интерфейсе, пропускается. Поле, которого нет в
строке, сохраняет значение по умолчанию из интерфейса, остаётся `undefined`,
если оно необязательное, а иначе это `TypeError` с его именем; колонка со
значением `NULL` даёт `null`.

Значения идут через `?`, никогда — в текст SQL: база получает их отдельно от
запроса, так что имя с кавычкой — просто имя. Значение — текст, число,
логическое или `null`, и в одном списке могут быть все сразу:
`[player.name, time, true, null]`.

Во что превращается колонка:

| Колонка | Значение |
| --- | --- |
| `INT`, `BIGINT`, `TINYINT`, `FLOAT`, `DOUBLE`, `DECIMAL`, `YEAR`, `BIT` | число |
| `CHAR`, `VARCHAR`, `TEXT`, `ENUM`, `SET`, `JSON` | текст |
| `DATE`, `DATETIME`, `TIMESTAMP`, `TIME` | текст, как его пишет MySQL: `"2026-10-12 18:30:00"` |
| `NULL` | `null` |

## Изменение строк

`db.execute(sql, params)` выполняет запрос, который меняет строки, —
`INSERT`, `UPDATE`, `DELETE`, `CREATE TABLE` — и отдаёт
`{ insertId, affectedRows }`:

```ts
const { insertId } = await db.execute("INSERT INTO records (steamId, map, time) VALUES (?, ?, ?)", [player.steamId, server.map, time]);
```

`insertId` — `AUTO_INCREMENT`-номер вставленной строки, `0`, если вставки не
было; `affectedRows` — сколько строк запрос вставил, изменил или удалил, а
для `UPDATE` — сколько строк подошло под условие.

## Ошибки

Неудачный запрос отклоняет промис с `DatabaseError`: `message` — текст
сервера, `code` — номер ошибки (`1062` — повтор ключа), `sqlState` — её
SQLSTATE (`"23000"`). Если запрос не дошёл до сервера — нет соединения,
неверный адрес, — `code` равен `0`, а `message` объясняет почему.

```ts
try {
	await db.execute("INSERT INTO players (steamId) VALUES (?)", [player.steamId]);
} catch (error) {
	if ((error as DatabaseError).code == 1062) return;   // уже есть
	console.error(`не удалось сохранить ${player.name}: ${error.message}`);
}
```

## Транзакции

`db.transaction(fn)` выполняет `fn` с транзакцией `tx`: то, что `fn`
отправила через `tx.query` и `tx.execute`, фиксируется, когда `fn`
вернулась, и откатывается, когда она бросила исключение, — ошибка уходит
дальше вызывающему. Промис отдаёт то, что вернула `fn`:

```ts
const runId = await db.transaction(async (tx) => {
	const { insertId } = await tx.execute("INSERT INTO runs (steamId, time) VALUES (?, ?)", [player.steamId, time]);
	await tx.execute("UPDATE players SET runs = runs + 1 WHERE steamId = ?", [player.steamId]);
	return insertId;
});
```

У транзакции, пока она идёт, своё соединение; на один адрес одновременно
идут до четырёх, пятая ждёт, пока одна из них закончится.

::: warning
- **Одно соединение на адрес.** Все плагины, открывшие один адрес, делят
  одно соединение, и их запросы выполняются по одному в порядке отправки;
  соединение остаётся открытым от карты к карте. Соединение, закрытое
  сервером, открывается заново для следующего запроса. Запрос, во время
  которого соединение оборвалось, завершается ошибкой и не отправляется
  повторно: `INSERT`, который сервер мог выполнить, не выполнится дважды.
- **Запрос может идти минуту.** Если сервер молчит 60 секунд посреди
  запроса, запрос завершается ошибкой.
- **Результат читается целиком,** до 64 МБ: запрашивайте нужные строки.
- **`TINYINT(1)` — число,** `0` или `1`, так MySQL хранит `BOOLEAN`:
  читайте его в поле `number`.
- **Целое больше 2^53** (`9007199254740993`, 64-битный id) теряет
  последние цифры в `number`: выбирайте его текстом, `CAST(id AS CHAR)`, в
  поле `string`.
:::

## Другие базы

Схема адреса выбирает, кто на него отвечает. `mysql://` встроен; другая
база — файл, веб-сервис, нативы Pawn-модуля — это провайдер, который
библиотека или сам плагин регистрирует через `Database.register`, и плагин
открывает её адреса так же, как адреса MySQL.

Провайдер — функция, которая даёт соединение для адреса:

```ts
class LogConnection implements DatabaseConnection {
	constructor(public url: string) {}

	query(sql: string, params: DatabaseValue[]): Promise<string> {
		return Promise.resolve<string>("[]");   // строки как JSON-текст: [{"name":"a","time":1.5}]
	}

	execute(sql: string, params: DatabaseValue[]): Promise<ExecuteResult> {
		console.log(`${sql} ${JSON.stringify(params)}`);
		return Promise.resolve<ExecuteResult>({ insertId: 0, affectedRows: 0 });
	}

	begin(): Promise<DatabaseTransaction> {
		return Promise.reject<DatabaseTransaction>(new DatabaseError("у лога нет транзакций"));
	}

	close(): void {}
}

Database.register("log", (url: string): DatabaseConnection => new LogConnection(url));

const log = new Database("log://anything");
```

- `query` отдаёт строки JSON-текстом — массивом объектов; `Database` читает
  его в `T` вызывающего.
- `execute` отдаёт `{ insertId, affectedRows }`.
- `begin` отдаёт `DatabaseTransaction` — `query`, `execute`, `commit()` и
  `rollback()` — или отклоняется, если транзакций у базы нет.
- Соединение выполняет запросы в том порядке, в каком их получило.

`JSON.stringify(params)` пишет значения JSON-массивом — готовым телом
запроса к веб-сервису.

Провайдер из библиотеки регистрирует себя, когда библиотеку импортируют, так
что плагин, который им пользуется, пишет одну строку:

```ts
import "@myorg/sqlite";

const db = new Database("sqlite://data/myplugin.db");
```

Адрес, для схемы которого провайдера нет, отклоняет каждый запрос с
`DatabaseError`, в котором перечислены схемы, что есть.
