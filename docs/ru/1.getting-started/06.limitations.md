title: Ограничения

Всё, на что может наткнуться плагин, в одном месте — и что писать вместо
этого. Почти о каждом пункте ниже скажут сборка, редактор или консоль
сервера; здесь можно посмотреть, что это значит.

## Язык

Плагин — это TypeScript, скомпилированный в WebAssembly, а затем в машинный
код. Что есть в TypeScript, но нет в плагине:

- **`throw` принимает `Error` или строку,** которая становится `Error` с ней
  в сообщении: `throw 42` не собирается. `catch` получает `Error` —
  `error.message`, `error.name`, `instanceof` для своего класса. Падение,
  которое не ошибка, — переполнение стека — завершает вызов мимо всех
  `catch`.
- **Нет юнионов из разных типов.** `number | string` и `cond ? 1 : "a"` не
  собираются. Юнионы строковых литералов (`"CT" | "TERRORIST"`), `T | null` и
  `T | undefined` работают, как и `true | false | "default"` и настройка
  «функция или список» вроде `enabled` в menu-core. Берите два параметра, две
  функции или общий базовый класс.
- **Нет `any` и `unknown`.** У каждого значения есть тип, когда плагин
  собирается.
- **Объектный литерал говорит свой тип значениями:**
  `const point = { x: 1, y: 2 }` собирается — числа, текст, булевы, `new`,
  массивы и объектные литералы из них говорят свой тип, — а
  `const who = { name: player.name }` сам по себе нет: объявите интерфейс
  (`const who: Who = { ... }`) или пишите литерал там, где тип известен, —
  аргументу-настройкам ничего не нужно.
- **Простой объект подходит туда, где ждут другой, когда поля те же и в том
  же порядке:** `{ x: 1, y: 2 }` — это `Point` из `x` и `y`, а
  `{ y: 2, x: 1 }` — нет.
- **`JSON.parse` говорят, что он читает:** `JSON.parse<Settings>(text)` или
  `JSON.parse(text) as Settings`; сам по себе он не собирается. Поле, которого
  в тексте нет и которое не необязательное и без значения по умолчанию, — это
  `TypeError`, а в JavaScript оно было бы `undefined`. `JSON.stringify` не
  принимает функцию-заменитель ([JSON](../4.data/02.fs.md#json)).
- **Нет регулярных выражений.** `/.../` не собирается, а `new RegExp`
  завершает вызов. Текст сравнивайте через `includes`, `startsWith`, `split`,
  `indexOf`.
- **Дата становится текстом через геттеры.** `toLocaleString`,
  `toLocaleDateString`, `toLocaleTimeString` и `Intl` нет, а `toString`,
  `toDateString` и `toTimeString` дают UTC; `toISOString` и `toUTCString` —
  как в JavaScript. Местное время — `getHours()`, `getDate()`, ... — по
  часовому поясу сервера ([время](../2.core/01.plugin.md#время-и-случайность)).
- **`String(x)` и `Boolean(x)` — не функции:** пишите `` `${x}` `` и `!!x`.
  `Number(text)` — функция.
- **Синтаксис, который не собирается:**

  | Не собирается | Пишите вместо |
  | --- | --- |
  | `const { a: { b } } = o`, `const { a, ...rest } = o` | разберите вложенный объект отдельной инструкцией; назовите поля |
  | `break outer`, `continue outer` | флаг или внутренний цикл в функции, которая делает `return` |
  | `function*`, `yield`, `for await` | массив или `async`-функции и `await` |
  | `#secret` | `private secret` |
  | `enum Color { Red = "red" }` | юнион строк: `type Color = "red" \| "blue"`; числовой `enum` работает |
  | `keyof typeof o` | тип, написанный явно; `keyof` от класса работает |
  | `get x(): number` в интерфейсе | поле `x: number` |

- **Полю класса со стрелкой, которая возвращает не простое значение, нужен
  тип:** `onTick = () => { ... }` и `double = (n: number) => n * 2`
  собираются; `label = () => this.makeLabel()` требует
  `label: () => string = () => this.makeLabel()`.

## Переменные и необязательные значения

- **Метод, который выполняется рано через базовый класс,** может прочитать
  переменную до её объявления как пустое значение, там где JavaScript бросил
  бы `ReferenceError`.
- **Необязательное логическое поле, прочитанное в переменную, забывает, что
  его не задали:** `const loud = options.loud; loud ?? true` — это `false`.
  Читайте само поле: `options.loud ?? true`.
- **Параметру `flag?: boolean` нужно значение по умолчанию:** пишите
  `flag = false`. Необязательным числам, строкам и объектам оно не нужно.
- **Отсутствующая строка печатается как `null`** в шаблоне, а не
  `undefined`: пишите `` `${options.label ?? ""}` ``.
- **`x!` от `null` сразу бросает `TypeError`,** а в TypeScript `!` ничего
  не делает, и JavaScript бросает, только когда значение используют.
- **Арифметика с `undefined`** даёт `undefined`, а не `NaN`: перед счётом
  подставьте значение через `??`.

## Async и промисы

- **`for await` и async-генераторы** не собираются.
- **`await` принимает промис,** а `Promise.all` — список промисов: обычное
  значение оборачивайте в `Promise.resolve(5)`.
- **`Promise.race` и `any` нужен один тип:** промисы `number` и `string` или
  `number` и `sleep` не собираются. Дожидайтесь их по одному.
- **`Promise.all` из разных типов принимает до 8 промисов;** у промисов
  одного типа и у списка такого предела нет ([async](../2.core/04.async.md)).
- **Обработчик события игры отвечает только до первого `await`**
  ([события игры](../2.core/02.hooks.md#async-обработчики)).
- **Ожидающая async-функция хранит до 4 КБ своего состояния;** функция,
  которой нужно больше, останавливается с сообщением в консоли.

## События, команды, форварды, таймеры

- **Имя события пишется строкой:** `server.addEventListener(name, ...)` с
  именем в переменной не собирается — по имени выбирается тип события. Так
  же пишется и поле обработчика `"playerchange"`: `{ field: "ghost" }`, а не
  переменная. Без `field` у `value` события нет типа: читайте поле у
  `event.player`.
- **Обработчик события игры отвечает всегда или никогда.** Тот, что должен
  отвечать лишь иногда, ничего не возвращает и вызывает
  `event.preventDefault()` — или отвечает всегда, повторяя правило игры для
  остальных случаев ([события игры](../2.core/02.hooks.md)).
- **Поля-векторы событий игры только для чтения** (`dir` у `traceAttack`,
  позиции у `fireBullets`): остановите событие и сделайте нужное сами.
- **Два поля событий игры — числа:** `lastHitGroup` у `pain`; `item` у
  `hasRestrictItem` читается как `Weapon`, но хранит номер предмета —
  берите `event.item.id`.
- **Событию одного класса сущностей нужен `classname`** (`primaryAttack`,
  `deploy`, `think`, `use`): без него обработчик не добавляется, а в консоль
  пишется строка. У события, которое доставил Ham Sandwich,
  `stopImmediatePropagation()` блокирует функцию игры, но не обработчики
  других плагинов ([события игры](../2.core/02.hooks.md#один-класс-сущностей)).
- **Аргументы сообщения читаются по одному виду:** `event.args.number(i)` или
  `event.args.text(i)` (`isText(i)` подскажет какой), а не массивом чисел и
  текстов вместе — значению любого из двух типов негде храниться. У частых
  сообщений есть типизированные поля ([Плагин](../2.core/01.plugin.md#сообщения-клиентам)).
- **Натив, который берёт обратный вызов по имени паблика**, — `register_think`,
  `set_native_filter` — получает его от `publicFor(handler, key)`.
- **У вашего натива до 64 аргументов** в том виде, в каком их передаёт Pawn, —
  массив или строковый результат считается дважды, вместе с размером; больше
  останавливает сборку ([нативы](../6.pawn/01.natives.md#правила)).
- **У форварда до 32 аргументов** — столько, сколько AMX Mod X даёт
  форварду. Аргументу `Team` или `RoundWinner` нужно объявление форварда в
  include. Форвард, который поднимает плагин на Pawn, доходит до TypeScript,
  только если он объявлен в include, который идёт с amxts, а массив среди его
  аргументов приходит целиком, только если include указывает размер массива
  (`Float:origin[3]`); массив без размера приходит пустым
  ([форварды](../2.core/03.forwards.md)).
- **В `"connect"`, `"authorized"` и `"putinserver"` игрок — это `Client`:**
  здоровья и оружия у него ещё нет ([плагин](../2.core/01.plugin.md#события-сервера)).
- **Таймер ждёт не меньше 0,1 секунды** и срабатывает на кадре сервера, как
  любой таймер AMX Mod X.
- **Прекэшировать можно только пока грузится карта:** `server.precache` на
  верхнем уровне файла или в событии `"precache"`. Плагин, перезагруженный
  посреди карты, события `"precache"` не получает; его верхний уровень
  находит файл, который карта уже прекэшировала, а файл, который тогда не
  прекэшировал ни один плагин, ждёт следующей карты. Модель, которую игре
  дали без прекэша, останавливает сервер
  ([плагин](../2.core/01.plugin.md#звуки-и-прекэш)).

## Цвета в чате и меню

- **Один цвет команды на сообщение в чате.** Красный, синий, серый и `!t`
  делят его: побеждает первый в строке, остальные показываются им же.
- **Каждое место рисует свои метки.** `!w` (белый) и `!R` (к правому краю) —
  для меню; `!g`, `!b` и `!t` — для чата. Метка, которую место не рисует,
  убирается из текста, и никто об этом не предупреждает.
- **У `"center"`, `"console"` и `"notify"` цветов нет:** текст показывается
  как написан, вместе с метками.
- **Регистр в метках важен:** `!R` — не красный ([цвета](../2.core/01.plugin.md#цвета)).
- **`lang.translate` принимает аргументы строками:** число передаётся
  текстом, `` `${seconds}` `` ([переводы](../2.core/01.plugin.md#переводы)). Строка
  словаря читается до 511 байт.

## Меню

- **menu-core пробовали в игре всего несколько раз;** его поведение ещё
  может измениться.
- **В коде требование — функция:** `enabled` и `visible` принимают проверку,
  а не имя, зарегистрированное для файлов меню (`IS_ALIVE`, `FLAG_d`), —
  пишите `(player) => player.isAlive`.
- **Плейсхолдеры `%name%` — для файлов меню и плагинов на Pawn.** В коде
  текст — функция: `` (player) => `Лечение (${player.health} HP)` ``.
- **`NAME:param` в файле меню забирает остаток строки** вместе с пробелами:
  пишите его после остальных имён в `visible`, `enabled` или `when`.
- **INI-меню не умеет скрывать пункт:** его столбец условия делает пункт
  серым; `visible` — это YAML и JSON ([меню](../../modules/ru/menu-core.md#столбцы-ini)).
- **Имя пункта в YAML или JSON не делится по `|`:** его варианты пишутся
  через `variants`.
- **Флаг INI-меню — это `YES` или `NO`:** на `true`, `1` или `yes` будет
  предупреждение с правильным словом, и это `NO`.
- **Текст с пробелами в INI-меню берётся в кавычки:** `TITLE = "Main menu"`;
  без кавычек читается только первое слово.
- **Цвет в файле меню — метка** `!y`: на коды Pawn (`\y`, `\r`) будет
  предупреждение, и они выбрасываются. Текст из Pawn — пункты плагина на
  Pawn, словарь lang — сохраняет свои коды.
- **Плейсхолдеры — `%time%` и `%target%`:** `%TIME%` и `%s` остаются как
  написаны.
- **`ADMIN` и `ACCESS_ADMIN` не встроены:** их регистрирует плагин, или
  пишите `IS_ADMIN` (любой админ) или `FLAG_<буквы>` (`FLAG_d`)
  ([меню](../../modules/ru/menu-core.md#поля)).

## Игроки и сущности

- **Свойствам сущностей нужен reapi, как и событиям игры, которые приходят
  от него.** Без него работают
  основное об игроке, действия с игроком (`give`, `respawn`, …) и
  `Entity.find`/`findAll`/`create` ([игроки](../3.game/02.players.md)).
- **Значение, для которого нет имени**, — его записал другой плагин или мод
  — читается как `"unknown"`, а присваивание `"unknown"` ничего не меняет.
  Число читайте нативом: `get_entvar(player.id, var_rendermode)`.
- **Простые числа:** `activity` и `idealActivity` (`ACT_*` модели),
  `autoWepSwitch`, `inSpecialReload`.
- **Нет свойства для:** членов-массивов (`m_rgAmmo`, …; оружие — это
  `player.items`), `var_controller`, `var_blending`. Берите `get_member` и `set_member`
  ([сущности](../3.game/01.entities.md#поля-которые-не-свойства)).
- **Векторному или текстовому полю, прочитанному нативом, нужен его тип:**
  `get_entvar<Vector>(id, var_origin)`, `get_member<string>(id, m_szAnimExtention)`.
  Без него поле читается числом, а векторное или текстовое поле читается как
  `0`, и в консоли появляется строка о том, что написать.
- **`player.health` — целое число;** `health` другой сущности — дробное.
- **Список флагов пишется обратно только через `push`:** `pop` и `splice`
  меняют массив, а не игру. Чтобы убрать флаг, присвойте отфильтрованный
  массив.
- **Общие поля игрока** — это `boolean`, `number`, `string`, юнион строковых
  литералов, `Player[]` или объект из них; необязательных не бывает, и члены
  объекта — не объекты. Имя, которое у `Player` уже есть, не принимается.

## Эффекты и прекэш

- **Нет эффектов для декалей** (дырки от пули, рисунка на стене — им нужен
  индекс декали), для цветов трассеров движка и для текстового сообщения
  (это `player.showHud`); их отправляют через `message_begin` и `write_*`
  ([эффекты](../3.game/03.effects.md)).
- **Некоторые размеры — собственные числа эффекта,** от `0` до `255`: `width`
  и `noise` луча, `scale` спрайта; описание каждой настройки говорит, чему
  равен один шаг.
- **Файл прекэшируется, только пока грузится карта.** Запрошенный позже файл,
  который не прекэшировал ни один плагин, — это строка в консоли, а эффект,
  который его рисует, не отправляется.

## Нативы и хранилище

- **Собственные нативы плагина** — это `export function` его файла с типами
  параметров из списка на странице [нативы](../6.pawn/01.natives.md); другой тип
  останавливает сборку.
- **После `amxts_reload`** натив, который добавила перезагрузка, есть только
  у плагинов на Pawn, загруженных позже.
- **Текст обрезают AMX Mod X и игра, а не путь до них:** натив получает
  строку целиком, до 16383 байт — столько AMX Mod X читает, и пишет в буфер
  не больше 16384 ячеек, какой бы длины он ни был. Натив с хвостом
  `const fmt[], any:...` (`client_print`, `server_print`, `format`, …)
  форматирует строку не длиннее 4095 байт, а `server_print` печатает из них
  254. Игра показывает около 190 байт строки чата — примерно 95 букв
  кириллицы — и 126 байт строки консоли, отправленной через `client_print`.
- **Длина буфера не бывает отрицательной:** натив, которому передан буфер и
  длина меньше 0 — `-1`, который `ArrayGetArray`, `ArrayPushArray` и другие
  нативы `cellarray` читают как «весь элемент», — не вызывается и отвечает
  `0`. Передавайте длину самого буфера.
- **`Storage` хранит текст:** `value.toString()` внутрь, `parseInt(value)`
  наружу. На диск он попадает при смене карты или нормальном выключении
  сервера; при падении пропадает всё, что записано после последней смены
  карты. Значение читается обратно до 255 байт UTF-8 — это около 127 букв
  кириллицы.

## Конфиги

### Типизированные конфиги — `configs.load`

- **У объекта `configs.load(name, { ... })` без типа нет имени типа,** поэтому
  его не принять параметром функции: объявите интерфейс и пишите
  `configs.load<Settings>(name, defaults)`.
- **Сборка читает форму из исходника** и отказывает, называя место и
  исправление: пустой список без типа, переменная со значениями по умолчанию
  без объявленного типа, список списков списков или объектов, `Map` списков
  или объектов, юнион не из имён (`number | string`), обобщённый интерфейс
  или интерфейс с `extends`, поле, названное строкой, тип, содержащий сам
  себя.
- **В ключах `Map` нет `.` и `[`:** такой ключ не прочитать и не записать.
- **В INI нет места для значения верхнего уровня, которое не объект, и для
  списка объектов:** такое поле остаётся со значением по умолчанию, и консоль
  один раз об этом говорит. Пишите такой конфиг в YAML или JSON.
- **В INI имена секций различают регистр, а ключи — нет:** `[CHAT]` — не
  `chat`.
- **Сохранение** пишет список YAML, записанный как `[a, b]`, по элементу на
  строку и выбрасывает комментарий после значения на той же строке и
  комментарии внутри `{ }` и `[ ]`. Комментарии на отдельных строках и пустые
  строки сохраняются.

### Файлы конфигов

- **Одно имя — один файл.** `configs.load("settings")` читает первый из
  `settings.ini`, `.yaml`, `.yml`, `.json`, `.jsonc`; если их два, в консоли
  будет ошибка, и прочитается первый.
- **Из YAML конфиги берут только часть.** Не читаются: якоря и ссылки (`&`,
  `*`), теги (`!`), сложные ключи (`?`), директивы, несколько документов,
  простое значение на несколько строк (возьмите его в кавычки или
  используйте `|` или `>`), табуляция в отступах, ключ, записанный дважды,
  ключ внутри `[ ]`. Каждое — ошибка с файлом, строкой и столбцом, и файл
  читается пустым.
- **`yes` и `no` в YAML — текст.** Типизированный конфиг принимает их как
  логическое значение; файлу меню нужны `true` и `false`.
- **Значение INI с пробелами берётся в кавычки:** `title = "Main menu"`. Без
  кавычек это список слов: нативы `cfg_*` Pawn и menu-core читают первое
  слово, а типизированный конфиг оставляет значение по умолчанию и говорит
  почему.
- **Элемент списка в пути — это `[0]`:** `items[0].name`; `items.0.name`
  ищет ключ `0`.

## Общие модули

Подробно — в [общих модулях](../5.modules/01.shared-modules.md).

- **То, что не передаётся между плагинами, не собирается:** `Map`, `Set`,
  `Record` с ключами из любых строк, обобщённый класс, класс из стандартной библиотеки, тип, который модуль не
  экспортирует, вычисляемое значение по умолчанию, обобщённая или
  `async`-функция, остаточный параметр, экспортированная переменная
  (`export let count`) — объект класса самого модуля
  (`export const counter = new Counter()`) передаётся.
- **Поле-массив или поле-объект общего объекта читается как копия:** `push`
  меняет копию. Пользуйтесь методом модуля или присваивайте поле целиком.
- **Каждый вызов копирует аргументы в обе стороны:** при запуске —
  нормально, каждый кадр — дорого.
- **Плагин модуля и те, кто его вызывает, собираются из одного исходника
  модуля;** плагин, собранный с другой версией, вместо вызова получит строку
  в консоли.

## Модули и команда `amxts`

- **Пока не в npm.** `npm create amxts` и установка из npm заработают, когда
  пакеты опубликуют; до тех пор создавайте проект с `--local`
  ([начало работы](02.quick-start.md#проект)).
- **Код модуля импортирует то, чем пользуется.** Автоимпорты доходят до
  плагинов проекта; файлы пакета модуля и файл в `modules/` папки плагинов
  собираются в проектах и на серверах, настроек которых не знают, поэтому
  называют свои импорты сами.
- **Модуль даёт одно имя**: себя пространством имён (`imports: [{ from, as }]`)
  или один из своих экспортов (`imports: [{ from, name }]`), а не список своих
  функций или типов; `menus.Menu` — тип из пространства имён.
- **Модуль, чьи нативы вызывают только Pawn-плагины, в сборку не попадает,**
  если его не называет `pawn` в `amxts.config.ts`: Pawn-плагины сборка не
  читает.
- **`meta`, `requires`, `defaults` и `imports` модуля — литералы:** сборка читает их, не
  запуская модуль. Кроме `setup`, у `defineModule` нет хуков жизненного цикла:
  подписывайтесь на события сервера внутри `setup`.
- **Тесты запускает `amxts test`,** то есть `bun test`; другие тестовые
  раннеры не поддерживаются.
- **Натив, на который фейковый сервер не отвечает, останавливает тест** с его
  именем; ответьте на него через `server.defineNative(name, native)` в тесте
  или в [тестовом наборе](../7.testing/01.index.md#тестовый-набор-модуля) модуля.

## Редактор

- **TypeScript 5.9, 6 и 7** работают в редакторе. Сборка и
  `amxts typecheck` используют TypeScript 5, который ставит ядро.
- **Поле, которое принимает редактор, может не найтись при сборке:**
  редактор видит поля, которые добавляет `Player` любой файл папки плагинов,
  а сборка — только поля файлов, которые плагин импортирует. Добавьте
  `import` файла, который его объявляет.
- **knip считает ядро и модули неиспользуемыми** в проекте, созданном с
  `--local`, где они подключены ссылкой.
- **Живая помощь в файлах меню — только в VS Code,** через расширение amxts
  ([меню](../../modules/ru/menu-core.md#подсказки-в-редакторе)).
- **Расширение знает имена, написанные строкой в рабочей папке.** Имя в
  переменной (`menus.addAction(name, ...)`) или имя, которое регистрирует
  только плагин на Pawn на сервере, — предупреждение в редакторе; в счёт идёт
  проверка сервера на его первом кадре.

## Сервер

- **Плагин собирается под систему своего сервера.** `.aot` — машинный код
  под Windows или под Linux, и собранный под другую систему не загрузится:
  консоль скажет `was compiled for a Linux server, and this one runs Windows`
  (или наоборот). Сборка узнаёт систему по `AMXTS_SERVER`; для сервера,
  которого она не видит, задайте `AMXTS_SERVER_OS` или передайте `--os`
  ([система сервера](03.cli.md#система-сервера)). `.ts`, который сервер
  компилирует сам, всегда подходит.
- **`.ts`, который компилирует сервер, задерживает сервер** на секунду-две,
  пока идёт компиляция: посреди раунда игра замирает. На сервер, где играют,
  выкладывайте `.aot`, собранные в проекте
  ([установка на сервер](04.install.md#написанные-на-сервере)).
- **Рекомендуем ReHLDS; на обычном HLDS не пробовали.** Без reapi нет
  свойств сущностей и событий игры, которые приходят от него.
- **AMX Mod X 1.9 или новее.**
